# Pealayer alpha contract

- The shared Flutter controller's current basic design is rejected. Coordinate one compact, professional, activity-oriented PCController/Pealayer workspace rather than separate product tabs. Use contextual connection toggles, real capability-driven cards/charts, semantic icon actions/pills and responsive phone/tablet headers/dialogs. Omit unavailable-only cards, filler narration and dormant peer access-token fields; multi-step authentication/authorization is deferred, not simulated.
- Keep appearance/branding, task/activity icon, palettes (including PakarController) and one/both launcher identities in shared app Preferences. DNS-SD/mDNS, SSDP and MNDP must agree across native hosts and Flutter. Auto-connect verified discoveries under saved intent without replacing a live selected peer, acquiring board authority or actuating outputs. Coordinate bounded, verified peer APK transfers/upgrades over IPC/RPC with Android consent and signature/package checks. Source/build/device captures never override David's rejection or establish physical acceptance.

- Alpha has one current API and persisted-data contract. Do not add build-number checks, rolling-upgrade branches, old field or method aliases, legacy migrations, or speculative future-version handling.
- Update Pealayer, PCController, firmware, the Web UI, tests, and documentation together when the contract changes. An obsolete build is replaced, not supported in parallel.
- Be tolerant of runtime faults, not obsolete schemas: validate authoritative responses, normalize bounded current-contract values, retain the last known-good state when a refresh is incomplete, and request an authoritative refresh after dropped or reordered events.
- Reject malformed required current-contract fields with a clear error. Never silently publish a false empty/default hardware state after a failed catalog read.
- Capability-driven behavior, OS/runtime safety checks, transport retries, and renderer fallbacks are operational fault tolerance. They are not version-compatibility shims and must not be removed merely because the project is in alpha.
- Use stable semantic IDs and typed machine-readable errors. Do not infer semantic state from labels, human error text, relay numbering, or other incidental presentation data.

## Verification and deployment

- Tests that exercise persistence must receive an isolated `PEALAYER_CONFIG_FILE` from the parent process before startup; never point fixtures at the user's OS configuration or Registry mirror. Pure catalog/model reconciliation must not save configuration or publish engine commands. Do not mutate process environment underneath libmpv/native threads to retrofit isolation.
- Every feature/fix pass includes a host-compatible Cafe-PC deployment and live verification, or an explicit deployment blocker. Do not call a local build delivered to Cafe-PC.
- Preserve and coordinate unpushed or separate host work before replacement. Package against the host's actual libmpv runtime and validate the manifest and runtime smoke test.
- Use application IPC/RPC to request graceful quit before replacement; use the peer updater rather than manually replacing a running executable. The user permits terminating an already-confirmed hung Pealayer process after graceful exit fails; preserve diagnostics first. This is not permission to terminate healthy unrelated processes.
- Never invoke egui Context accessors, widgets, or repaint callbacks from inside input/data/memory/output transactions; the context lock is non-reentrant. Snapshot inputs first, then perform the narrow transaction.
# Continuity and native Windows assets

- Modal corner-close controls must use `ui::dialog::close_button`, whose paint, hit target and focus outline share an exact square independent of text padding. Use `confirmation_modal` for unsaved-change prompts; do not reintroduce stock text-sized × buttons. Keep geometry and non-destructive Close/Escape regression coverage across fonts, display scales and interaction states.

- On Windows, Pealayer-owned source, caches, staging and runtime files belong under `%LOCALAPPDATA%\Programs\Pealayer`. The canonical source is `source\Pealayer`, the shared Cargo cache is `build-cache\cargo-target`, and the running executable is `bin\pealayer.exe`. `C:\development` is reserved for development tools, not Pealayer checkouts or build artifacts. Use the shared Windows path resolver rather than inventing another checkout/cache path; preserve existing work when relocating it.
- GitHub is the source of truth. Before each handoff, audit all relevant worktrees and local-only commits, push useful source/tests/docs/scripts to named branches, verify exact GitHub refs, and record the owning issue/PR, tests, blockers and next action. Preserve concurrent/user work; never reset or clean it away.
- Never publish credentials, private settings/media URLs, user artwork, caches, logs or generated-only artifacts. Back up private runtime state separately before proposing a machine wipe; clean repository worktrees alone do not establish wipe readiness.
- Windows custom application, playback-state, taskbar, titlebar, shortcut and executable-resource icons must use native multi-resolution ICO files, generated with high-quality resampling. Private raster masters may remain as authoring inputs; browser/PWA assets may use web-required formats. Patch executable resources before signing.
- Consult `docs/verification/agent-handoff.md` for the current continuation checklist, production-host build restriction and host-specific runtime safety rules. Treat its runtime observations as dated evidence, not current health.

## Human-facing history and acceptance

- Keep completed issue/PR summaries concise and product-focused. Put exact source/runtime hashes, measured timestamps and host-specific deployment receipts in linked technical evidence, not repeated finished-task prose. Preserve safety requirements, meaningful version references and actual acceptance limits; do not erase evidence to make an issue look complete.
- Read the commit history before writing changelogs. Group actual changes by domain, maintain curated version notes and correct labels, and publish verified stable milestones with the matching packaged artifacts. Do not attribute later changes or screenshots to an older release. Genuine intermediate captures are useful; reconstructed historical images are not evidence.
- Use `docs/verification/CURRENT-ACCEPTANCE.md` for current remaining gates. A historical unchecked implementation item can be superseded by later delivered work without declaring its human, audio or physical acceptance passed.
- When human intervention is genuinely needed, use the existing APIs for an advertised appropriate buzzer melody with bounded repeats and a large Persian message on the production desktop. Stop attention when acknowledged; never leave an unbounded sound loop or use motion/relays as an alert. Routine progress does not need an alert.
- Diagnose excessive CPU with bounded live samples and trace its actual owning application/path before fixing it. Preserve fast event-driven playback/telemetry while reducing unchanged idle work; a short paused sample is not sustained playing, taskbar-preview or physical-timing acceptance.
- Every changed peer hardware snapshot must invalidate `hardware_revision` before its repaint notification. Use `four_d::engine::install_hardware_snapshot` for complete snapshot replacement; repaint alone does not invalidate `advertised_hardware`. Retain cached/paused RGB-only update regressions and suppress unchanged-snapshot churn.
- Native board tray selections must carry the menu's source/board target and revalidate live capability, connection, latch and busy state before dispatch. Keep E-STOP release on the existing GUI confirmation path; opening/testing a menu must not actuate hardware or add polling.
- UI fixtures that set simulated engine connection flags must use `memory_only_test_engine`, not `spawn_engine`'s background worker. The worker owns those flags and can overwrite fixtures nondeterministically; the memory-only fixture has no transport and fails accidental command dispatch closed.
- Native OS media transport has one registration: Windows uses the HWND-owned `windows_media_session` adapter, other platforms use Souvlaki. Do not attach a second Windows/global media-key listener. Retain all callback tokens, active guards and dispatch-time scope/capability validation. Session metadata uses cached factual tags; position/branding publication is bounded and must not add per-frame probes, artwork writes or invented capabilities. See `docs/verification/os-media-session.md`.
- Prepared hardware plans must acknowledge the coordinator's actual pause before replacement. Empty plans still require clear/clock ACKs but have no executor to arm; preserve pending explicit Play until those ACKs are fresh and matching. Old-revision ACKs must not erase new preparation/compilation failures or cancel a new retry. Keep timing faults latched and the 50 ms execution/250 ms freshness guards unchanged; see `docs/verification/hardware-preparation-recovery.md`.
- Caption alignment must be resolved from application direction and logical text, never `ui.layout().main_dir`: headers intentionally reverse widget allocation to anchor trailing actions even in LTR UI. Use explicit `aligned_click_label` alignment matching the inline editor. Retain painted-position tests for both seat cards, compact/normal headers and real RTL text; see `docs/verification/hardware-caption-alignment.md`.
- Reserve density/font-aware hardware header height before laying out its icon, caption, identifiers and trailing actions. Display and inline rename must keep the same font, inset and slot. Relay ON/OFF actions use semantic green/red across native/Web/mobile controls, not selection/accent colors; disabled safety states remain muted.
- Effects Library display/rename headers must share grip/icon/name slots, action gutter, font/line-height and inset. Use the fixed-slot shared searchable icon trigger; a stock combobox must not widen or raise rename rows. Compare actual glyph baselines (including RTL row offsets), card bounds and metadata while toggling modes; see `docs/verification/effect-card-rename-geometry.md`.
- Standard input/selector/menu density comes from `ui::control_density` and the shared `ui_control_density` appearance preference. Never reuse a fixed menu-row height for a closed custom selector or add a second density constant. Use the shared open chevron, preserve exact ComboBox identities, and retain both-theme/scale/large-font geometry tests. Inline caption editing remains in its matching display slot.
- Buzzer Stop is enabled from coordinator-owned activity, including bounded tone tests, not connection alone. Stops remain available under E-STOP but respect connection/busy state. Never play a physical tone merely to verify button styling; see `docs/verification/control-density-and-buzzer.md`.
- Effect Designer and main timeline wheel routing share original event axes/units and preference modifier precedence. Claim only the visible canvas, preserve outer-dialog/field input, and keep pointer-anchored zoom regressions. Same-kind direct channel retargeting must isolate one placement and preserve values/action edges; never relax published macro targets or regenerate an Off cue as On.
- For live visual acceptance, inspect application-owned screenshot/export features and the maintained capture utilities before treating an external desktop-capture failure as a permanent blocker. `scripts/capture-visible-window-windows.ps1` can capture the existing Pealayer window without launching, focusing, moving or clicking it; use `-RenderOccludedWindow` for a best-effort PrintWindow capture, then inspect the result for a real, nonblank current UI. Store private production captures under the program root's `verification` directory, not in Git. A video-only frame or cached taskbar thumbnail is not proof of the native UI or physical seat motion.
